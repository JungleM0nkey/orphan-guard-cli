# Go CLI implementation plan

**Goal:** Build and install a standalone Windows Go CLI for detecting and deliberately cleaning up orphaned processes.

**Authority:** User requested setup of JungleM0nkey/orphan-guard-cli and implementation of its missing CLI in Go. The existing Python tray application defines the profile schema and window/process/blocklist rules.

**Architecture:** A single `cmd/orphan-guard` package with standard-library argument parsing, pure candidate selection, and native Windows process/window APIs. The Python application remains usable independently. No polling, startup tasks, or background monitor.

## Scope and constraints

- Commands: `scan`, `clean`, `init`, `version`, and help; text and versioned JSON output.
- Without `--config`, report same-session processes with missing or reused parent PIDs as candidates, not proof that a background application is abandoned.
- With `--config`, use enabled profiles and the upstream indicator modes. Ignore `auto_kill`; only explicit `clean --apply` terminates anything.
- Default minimum process age: one minute; expose `--min-age` for deliberate overrides.
- Critical Windows processes, Herdr/agent processes, this CLI, and its live ancestors are protected.
- Cleanup previews by default. Applying requires a named profile or a single PID; PID cleanup additionally requires the start timestamp from the scan.
- Open and terminate the same process handle after verifying its creation time and executable identity. Recheck current eligibility before cleanup.
- No new Go dependencies, no forced privilege escalation, no process-tree killing.

## Files and interfaces

- `cmd/orphan-guard/scan.go`: process/snapshot/profile/candidate types and `findCandidates(snapshot, []profile, scanOptions) ([]candidate, error)`.
- `cmd/orphan-guard/config.go` and `defaults.json`: strict config loading and exclusive creation of disabled default profiles, compatible with the tray JSON schema.
- `cmd/orphan-guard/process_windows.go`: `takeSnapshot() (snapshot, error)` and `terminate(process) error` using native Windows APIs.
- `cmd/orphan-guard/process_other.go`: explicit unsupported-platform errors.
- `cmd/orphan-guard/main.go`: CLI parsing, reports, selection, timestamp checks, and exit codes.
- Matching `_test.go` files: selection/validation boundaries and real disposable-process smoke tests.
- `README.md` and `.gitignore`: CLI setup, commands, safety semantics, and build artifacts.

## Review focus

1. PID reuse between snapshots or between agent scan and cleanup must never kill a replacement.
2. An inaccessible parent is not a missing parent; unverified targets fail closed.
3. Window-profile indicators must not be confused with titleless/background windows.
4. Overlapping profiles, disabled profiles, malformed config, and missing selections must be deterministic and safe.
5. A native integration test must clean up only its own disposable child processes, including on failure.
